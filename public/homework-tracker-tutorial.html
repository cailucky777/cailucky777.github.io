Section 1

Create the Xcode project

Every SwiftUI app starts with a brand-new Xcode project. You'll create one now and take a quick tour of the starter code before writing anything of your own.

⏱ About 5 minutes
1

Open Xcode and start a new project.

Launch Xcode, choose File › New › Project…, and pick the iOS tab. Select the App template, then click Next.

2

Configure the project options.

Fill out the form with these values:

  • Product Name: HomeworkTracker
  • Interface: SwiftUI
  • Language: Swift
  • Storage: None

Click Next, choose a folder to save the project, and click Create.

3

Look at the starter file.

In the Project navigator, open ContentView.swift. This is where the screen of your app lives. The template shows a globe icon and the words "Hello, world!". Click the Resume button at the top of the preview area to see it running.

ContentView.swift · starter
import SwiftUI

struct ContentView: View {
    var body: some View {
        VStack {
            Image(systemName: "globe")
                .imageScale(.large)
                .foregroundStyle(.tint)
            Text("Hello, world!")
        }
        .padding()
    }
}
Tip: If the preview doesn't appear, choose Editor › Canvas (or press ⌥⌘↩) to show it.
Section 2

Model homework with a custom type

Before you can show homework on the screen, you need to decide what a piece of homework is. You'll capture that idea in code by writing a Swift struct—a custom type that bundles related values together.

⏱ About 10 minutes
1

Add a new Swift file to the project.

In the Project navigator, right-click the HomeworkTracker folder and choose New File…. Select Swift File, name it Homework.swift, and click Create.

2

Define the Homework struct.

Replace the contents of the file with a struct that holds the information you'd want for any assignment: the class subject, what needs to be done, when it's due, and whether it's finished.

Homework.swift
import Foundation

struct Homework {
    var subject: String
    var title: String
    var dueDate: Date
    var isCompleted: Bool = false
}

Each line inside the braces declares a property—a piece of data the struct stores. Notice that isCompleted has a default value of false, so new homework starts out unfinished.

3

Add a priority level using an enum.

Not all homework is equally urgent. Add a Priority enum above the struct so you can mark each task as high, medium, or low priority.

Homework.swift
import Foundation

enum Priority: String, CaseIterable {
    case high = "High"
    case medium = "Medium"
    case low = "Low"
}

struct Homework {
    var subject: String
    var title: String
    var dueDate: Date
    var isCompleted: Bool = false
    var priority: Priority = .medium
}

The highlighted lines are what you're adding. CaseIterable lets you ask Swift for every priority case later (handy for menus and pickers).

4

Make Homework conform to Identifiable.

SwiftUI's List needs a way to tell items apart. The easiest way is to make your type conform to the Identifiable protocol, which requires a unique id property.

Homework.swift
struct Homework: Identifiable {
    let id = UUID()
    var subject: String
    var title: String
    var dueDate: Date
    var isCompleted: Bool = false
    var priority: Priority = .medium
}

UUID() generates a brand-new universally unique identifier every time a Homework is created, so no two assignments ever share an id.

Why this matters: When SwiftUI redraws your list, it uses id to figure out which rows are new, which moved, and which went away. Without it, animations and updates wouldn't work correctly.
Section 3

Add sample data

To see the app come alive, you need something to display. You'll add a collection of example assignments to Homework itself so any view can grab them while you're designing.

⏱ About 5 minutes
1

Add a static sampleData array.

Below the closing brace of Homework, add an extension that holds a few realistic assignments. Using .addingTimeInterval(86_400) shifts a date by one day (there are 86,400 seconds in a day).

Homework.swift
extension Homework {
    static let sampleData: [Homework] = [
        Homework(
            subject: "Math",
            title: "Chapter 5 problems 1–20",
            dueDate: .now.addingTimeInterval(86_400),
            priority: .high
        ),
        Homework(
            subject: "English",
            title: "Draft of persuasive essay",
            dueDate: .now.addingTimeInterval(86_400 * 2)
        ),
        Homework(
            subject: "Science",
            title: "Lab report on photosynthesis",
            dueDate: .now.addingTimeInterval(86_400 * 3),
            priority: .low
        ),
        Homework(
            subject: "History",
            title: "Read chapters 7 and 8",
            dueDate: .now.addingTimeInterval(86_400 * 5),
            isCompleted: true
        )
    ]
}
Tip: Sample data lives in the model so any view—or future Xcode preview—can use it. You'll appreciate this when you start adding more screens.
Section 4

Display a list of homework

Now that the data exists, it's time to show it. SwiftUI's List and ForEach turn a collection of values into rows on the screen with almost no boilerplate.

⏱ About 8 minutes
1

Open ContentView.swift.

Replace the body of ContentView with a navigation stack that wraps a List.

ContentView.swift
import SwiftUI

struct ContentView: View {
    var body: some View {
        NavigationStack {
            List {
                ForEach(Homework.sampleData) { homework in
                    Text(homework.title)
                }
            }
            .navigationTitle("Homework")
        }
    }
}

The ForEach walks through every entry in sampleData. Because Homework is Identifiable, SwiftUI knows how to tell the rows apart automatically—no id: parameter required.

2

Preview it.

Click Resume in the canvas. You should see a scrolling list with four rows and a large Homework title at the top.

Section 5

Build a custom row view

A single line of text doesn't tell students much. You'll extract the row into its own view so it can show the subject, title, due date, and a colored priority badge.

⏱ About 12 minutes
1

Create HomeworkRow.swift.

Add another Swift file the same way as before, name it HomeworkRow.swift, and replace the contents with this starting view.

HomeworkRow.swift
import SwiftUI

struct HomeworkRow: View {
    let homework: Homework

    var body: some View {
        HStack {
            VStack(alignment: .leading, spacing: 4) {
                Text(homework.subject)
                    .font(.caption)
                    .foregroundStyle(.secondary)
                Text(homework.title)
                    .font(.headline)
                Text(homework.dueDate, style: .date)
                    .font(.caption)
                    .foregroundStyle(.secondary)
            }
            Spacer()
        }
        .padding(.vertical, 4)
    }
}

The row receives one piece of homework as a constant (let) and arranges its fields in a vertical stack.

2

Add a priority badge.

Add two computed properties below body that build a colored capsule based on the homework's priority, then place the badge inside the HStack.

HomeworkRow.swift
        HStack {
            VStack(alignment: .leading, spacing: 4) { /* …unchanged… */ }
            Spacer()
            priorityBadge
        }
        .padding(.vertical, 4)
    }

    private var priorityBadge: some View {
        Text(homework.priority.rawValue)
            .font(.caption2.bold())
            .padding(.horizontal, 8)
            .padding(.vertical, 4)
            .background(priorityColor.opacity(0.18))
            .foregroundStyle(priorityColor)
            .clipShape(Capsule())
    }

    private var priorityColor: Color {
        switch homework.priority {
        case .high: return .red
        case .medium: return .orange
        case .low: return .green
        }
    }
}
3

Use HomeworkRow in ContentView.

Switch back to ContentView.swift and replace the Text inside ForEach with your new row.

ContentView.swift
            List {
                ForEach(Homework.sampleData) { homework in
                    // Before:
                    // Text(homework.title)
                    HomeworkRow(homework: homework)
                }
            }

Section 6

Manage data with @State

Right now the homework list is a constant—nothing can change. By turning it into @State, you let the view own the data and automatically redraw whenever it changes.

⏱ About 8 minutes
1

Store the list as state.

In ContentView, add a @State property that starts with the sample data, then use it in the list.

ContentView.swift
struct ContentView: View {
    @State private var homeworkList: [Homework] = Homework.sampleData

    var body: some View {
        NavigationStack {
            List {
                ForEach(homeworkList) { homework in
                    HomeworkRow(homework: homework)
                }
            }
            .navigationTitle("Homework")
        }
    }
}
What @State does: it tells SwiftUI "this value belongs to the view, and the screen needs to refresh whenever it changes." private keeps it from being modified outside the view.
2

Add swipe-to-delete.

Because homeworkList can change, you can also let users remove items. Add a single modifier to ForEach.

ContentView.swift
                ForEach(homeworkList) { homework in
                    HomeworkRow(homework: homework)
                }
                .onDelete { indexSet in
                    homeworkList.remove(atOffsets: indexSet)
                }

Run the preview, swipe a row from right to left, and tap Delete. The row disappears and SwiftUI animates the change for free.

Section 7

Toggle completion with @Binding

You want students to tap a circle to mark homework done. That tap happens inside HomeworkRow, but the data lives in ContentView. You'll connect them with @Binding—a two-way reference that lets a child view read and write a value its parent owns.

⏱ About 12 minutes
1

Change HomeworkRow to use a binding.

Replace let homework with @Binding var homework. The body stays the same.

HomeworkRow.swift
struct HomeworkRow: View {
    @Binding var homework: Homework

    var body: some View {
        HStack {
            // …
        }
    }
}
2

Add a tappable checkmark.

Put a button at the very front of the HStack that flips isCompleted. The button's image changes based on the current value.

HomeworkRow.swift
        HStack {
            Button {
                homework.isCompleted.toggle()
            } label: {
                Image(systemName: homework.isCompleted
                                  ? "checkmark.circle.fill"
                                  : "circle")
                    .font(.title2)
                    .foregroundStyle(homework.isCompleted ? .green : .secondary)
            }
            .buttonStyle(.plain)

            VStack(alignment: .leading, spacing: 4) { /* …unchanged… */ }
            Spacer()
            priorityBadge
        }
Why .buttonStyle(.plain)? Without it, tapping anywhere in the row would trigger the button. The plain style shrinks the tap target back to just the icon.
3

Strike through completed titles.

Inside the inner VStack, add a modifier to the title so finished work is visually crossed out.

HomeworkRow.swift
                Text(homework.title)
                    .font(.headline)
                    .strikethrough(homework.isCompleted)
                    .foregroundStyle(homework.isCompleted ? .secondary : .primary)
4

Pass the binding from ContentView.

Back in ContentView.swift, switch ForEach to its binding form by prefixing the array with $. Each loop variable becomes a binding too.

ContentView.swift
            List {
                ForEach($homeworkList) { $homework in
                    HomeworkRow(homework: $homework)
                }
                .onDelete { indexSet in
                    homeworkList.remove(atOffsets: indexSet)
                }
            }
The dollar sign: $homeworkList hands out a binding instead of a copy. $homework inside the loop lets the child view write straight back into the array.
5

Run it and tap a row.

Press play in the preview. Tap any circle—watch the row dim, the title cross out, and the checkmark fill in. SwiftUI handled all of that for you because the view body is a function of the state.

Section 8

Concept breakdowns

Now that the app works, slow down and unpack the six ideas that did the heavy lifting. Each card pulls the relevant code out on its own and peels it back, line by line.

1. Identifiable data models (modeling)
Swift ⤓ ⧉
struct Homework: Identifiable {
    let id = UUID()           // 1. Permanent unique identity
    var subject: String          // 2. Mutable properties
    var title: String
    var dueDate: Date
    var isCompleted: Bool = false // 3. Default value
    var priority: Priority = .medium
}
  • struct defines a value type. Each Homework is its own independent copy — passing one around never accidentally shares state with another row.
  • Identifiable is a protocol whose only requirement is an id property. SwiftUI uses this id to tell rows apart inside a List.
  • UUID() generates a globally-unique value the instant the struct is created, so two assignments can never collide — even ones with the exact same title.
  • let id (not var) locks the identity for life: the subject and title can change, but the id never does.
  • Why it matters Without Identifiable, SwiftUI loses track of which row is which, and inserts, deletes, and reorders animate incorrectly — or not at all.
2. Static sample data (extensions & type-level storage)
Swift ⤓ ⧉
extension Homework {
    static let sampleData: [Homework] = [   // 1. Belongs to the type, not an instance
        Homework(subject: "Math",
                 title: "Chapter 5",
                 dueDate: .now.addingTimeInterval(86_400),
                 priority: .high)                  // 2. Trailing properties take defaults
        // …more entries…
    ]
}
  • extension adds functionality to an existing type without touching its original file. Great for keeping the core model lean while still attaching test data to it.
  • static let means the value lives on the type itself. You access it as Homework.sampleData — never instance-by-instance.
  • Putting sample data on the model means every view and every Xcode preview can grab the same realistic examples with one line.
  • Notice the call to Homework(...) only sets some properties — the rest fall back to the defaults defined on the struct (isCompleted = false, etc.).
  • Trade-off Perfect for development; in a shipping app you'd swap this for data loaded from disk, SwiftData, or a server.
3. Dynamic list rendering (data-driven views)
Swift ⤓ ⧉
NavigationStack {
    List {
        ForEach(homeworkList) { homework in   // 1. Iterate the array
            HomeworkRow(homework: homework)        // 2. One row per element
        }
    }
    .navigationTitle("Homework")                  // 3. Large title at the top
}
  • List gives you native iOS table styling — scrolling, separators, swipe actions — for free. You never write layout math.
  • ForEach(collection) walks the collection and emits a child view per element. The closure parameter homework is one element at a time.
  • Because Homework is Identifiable, no id: argument is needed — SwiftUI just reads homework.id automatically.
  • NavigationStack wraps the screen so you can later add titles, toolbars, and detail-view pushes without restructuring anything.
  • Chain reaction array exists → ForEach iterates → emits one HomeworkRow per element → List stacks them as native rows.
4. View-owned mutable data (@State + automatic redraw)
Swift ⤓ ⧉
@State private var homeworkList: [Homework] = Homework.sampleData

List {
    ForEach(homeworkList) { homework in
        HomeworkRow(homework: homework)
    }
    .onDelete { indexSet in                  // 1. User swipes a row
        homeworkList.remove(atOffsets: indexSet)  // 2. Mutate state directly
    }
}
  • @State tells SwiftUI "this data belongs to the view and will change." The value is stored outside the struct so it survives every body re-run.
  • private hides the state from the outside world — state is a local detail, not part of the view's public interface.
  • .onDelete is a modifier on ForEach that adds swipe-to-delete. SwiftUI hands you the indexSet of rows the user removed.
  • You never call "refresh" or "reload." Mutating homeworkList is the refresh — SwiftUI watches the assignment and rebuilds the body.
  • Chain reaction swipe to delete → array shrinks → @State detects the change → body re-runs → ForEach walks the new array → the missing row animates out.
5. Two-way binding (@Binding + the $ prefix)
Swift ⤓ ⧉
// Parent: ContentView.swift
ForEach($homeworkList) { $homework in      // 1. $ → binding to each element
    HomeworkRow(homework: $homework)         // 2. Hand the binding to the child
}

// Child: HomeworkRow.swift
struct HomeworkRow: View {
    @Binding var homework: Homework         // 3. Reference back to the parent
}
  • $homeworkList (with the dollar sign) hands out a binding to the array instead of a copy. Bindings are like a remote control — read and write the original.
  • ForEach($collection) is a special overload that yields element-level bindings. Each $homework in the loop is itself a binding into the array.
  • @Binding in the child says "I don't own this value — I just hold a reference." Any write inside the child goes straight back to the parent's @State.
  • Two property wrappers, one pipe: @State is the source of truth, @Binding is the wire. Together they keep parent and child perfectly in sync.
  • Mental model @State = "I own it." @Binding = "I borrow it." $ = "give me the wire to it."
6. Reactive UI from a single tap (interaction logic)
Swift ⤓ ⧉
Button {
    homework.isCompleted.toggle()                // 1. Flip the Bool in place
} label: {
    Image(systemName: homework.isCompleted
                       ? "checkmark.circle.fill"   // 2. When true
                       : "circle")                // 3. When false
        .foregroundStyle(homework.isCompleted ? .green : .secondary)
}
.buttonStyle(.plain)                             // 4. Don't make the whole row tappable
  • Button { action } label: { view } uses two trailing closures: the first runs on tap, the second describes how the button looks.
  • .toggle() is a Bool method that inverts the value in place. It works because homework is a binding writing back through to the array.
  • The ternary condition ? a : b lets the icon name and color depend on the current state without an if block — keeping the view a clean expression.
  • .buttonStyle(.plain) shrinks the tap target back to just the icon. Without it, tapping anywhere in the row would trigger the button.
  • Chain reaction tap → action fires → isCompleted flips → binding writes to the array → @State notices → body re-runs → icon, color, and strike-through all update — in a single frame.
Section 9

Check your understanding

Test what stuck. Try to answer each question before you reveal the explanation.

1. Why does Homework need an id?

What goes wrong if you remove the Identifiable conformance?

Reveal answer
List and ForEach need to tell each row apart to animate inserts, deletes, and reorders. Without an id you'd have to provide one with id: \.someProperty—and if two rows had matching values, SwiftUI would treat them as the same row and the UI would behave unpredictably.

2. What's the difference between let and @State?

Reveal answer
A let property is fixed for the lifetime of the view—you can read it but never assign to it. A @State property can change, and SwiftUI watches it: whenever the value updates, the view body is recomputed and the screen redraws.

3. Why use @Binding in HomeworkRow instead of @State?

Reveal answer
@State would mean the row owns its own copy of a homework value—changes there wouldn't reach the array in ContentView. @Binding is a reference back to the parent's data, so toggling the checkbox actually updates the source of truth.

4. Where would you add code to create a new homework?

Reveal answer
You'd add a toolbar button on the NavigationStack that shows a sheet containing a form. The form's Save button would append a new Homework to homeworkList. Because the array is @State, the list updates instantly. Try it as homework!
